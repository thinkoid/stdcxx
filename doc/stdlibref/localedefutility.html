Summary

A utility program to define a localization environment.

Synopsis

 
localedef [-c] -f charmap -i sourcefile name

Extensions of this implementation:

localedef [-c][-w][-wN][--no_position] -f charmap -i sourcefile         [-d output_dir][-I source_dir] name
localedef --help | -?
localedef --tokens file...
localedef --charmap charmap
localedef --values | --ctype | --collate | --census | --collate-numbers         -f charmap -i sourcefile [-I source_dir]

Description

The localedef utility reads a locale definition file, the definitions its copy statements name, and a character set description file, and translates them into binary files suitable for interpretation by this implementation of the C++ Standard Library. The binary files produced by localedef are referred to in this document as locale databases. In particular, the localization library makes use of this information to implement its behavior. Beside the locale database the utility writes the codecvt database of the character set, once per character set. The forms that begin with --tokens, --charmap, --values, --ctype, --collate, --census or --collate-numbers print what the utility read and write no database; each is the check of one part of the utility.

Options

Table 25 illustrates options that conform to the requirements of the IEEE Std 1003.1-2001 (POSIX) standard.

Table 25: localedef option requirements of the IEEE Std. 1003.1-2001 (POSIX) standard 

Option Meaning

-c

Create output regardless of warnings.

-f charmap

Use charmap as the pathname of the character set description file. This implementation requires the option.

-i sourcefile

Use sourcefile as the pathname of the locale description file. This implementation requires the option; localedef does not read its standard input.

The POSIX option -u is not supported.

Table 26 illustrates options that are provided as extensions to the IEEE Std 1003.1-2001 (POSIX) standard.

Table 26: localedef option extensions to the IEEE Std 1003.1-2001 (POSIX) standard 

Option Meaning

-w

Disable all warnings. A warning is still counted, and without -c it still withholds the output.

-wN

Disable warning number N, where N is a non-negative integer. The option can be repeated any number of times to disable multiple warnings. As with -w, the warning is still counted.

-d output_dir

Create the locale database under output_dir, as output_dir/name.

-I source_dir

Read the locale definitions that copy statements name from source_dir. Without the option they are read from the directory of sourcefile.

--no_position

Write a forward,position collation level as forward.

--help, -?

Print a usage message to stdout and exit with 0 exit status.

--tokens file...

Print the tokens of each line of the files.

--charmap charmap

Print the entries of the character set description file.

--values

Print the values of the four scalar categories, LC_NUMERIC, LC_MONETARY, LC_TIME and LC_MESSAGES.

--ctype

Print the classes, case maps and transliteration of LC_CTYPE.

--collate

Print the declarations and the collation sequence of LC_COLLATE.

--census

Print, for each character class, the number of characters the POSIX class defaults add to LC_CTYPE beyond the statements of the definition.

--collate-numbers

Print the collation numbering of the definition: the collating values, the rows and the weights.

The options of the first form may be given in any order. In the other forms the long option comes first. The forms that print take -f and -i, and -I, as the synopsis shows, and write no files.

Operands

The following operands are accepted:

    name

    The name of a locale database to produce. With -d it is taken relative to output_dir. Otherwise, if name contains at least one slash character it is considered to be a pathname, and will be created under the directory tree specified; if not, name is considered to be a filename and will be created in the current working directory. Directories along the path that do not exist are created.

Environment Variables

 
RWSTD_SRC_ROOT

    localedef reads no environment variable, this one included. The character set description file and the locale definition file are the pathnames that -f and -i give. The locale utility reads RWSTD_SRC_ROOT.

Input

localedef reads the locale definition from the filename specified with the -i option. The utility also reads the files named by any copy directives that appear in the locale definition, from the directory specified with the -I option, or from the directory of the locale definition. localedef reads the character set description from the file specified with the -f option.

The required format of the character set description file follows that described in section 6.4, Character Set Description File, of IEEE Std 1003.1-2001.

The required format of the locale definition file follows that described in section 7.3, Locale Definition, of IEEE Std 1003.1-2001.

Any files that conform to the required format can be used with localedef to produce binary locale database files suitable for use with the Apache C++ Standard Library.

A limited number of character set description files and locale definition files in the conforming format can be purchased from The Open Group. See http://www.opengroup.org/pubs/catalog/lo.htm.

Character set description files and locale definition files in an extended format can be obtained without charge from the JTC1/SC22/WG15 -- POSIX pages at ftp://dkuug.dk/i18n/WG15-collection/. These files are distributed with the Apache C++ Standard Library sources.

Additionally, the localedef utility also accepts files in an extended format used by GNU C library, glibc 2
(http://www.gnu.org/software/libc/libc.html). It reads them by the lexical rules of glibc's own localedef, and it reads the locale definitions and character set description files of glibc 2.44. The locale definition files that accompany glibc 2.2.5 are distributed with the Apache C++ Standard Library sources.

Output

On success, localedef will create one or more files. It creates the directory name, under output_dir when -d is given, and writes the locale database into it. It writes the codecvt database of the character set, the encoding file, into the directory that holds name, unless a file of that name is there already. The following directory tree describes the organization of the output files:

    encoding
    name    /
    name/LC_COLLATE
    name/LC_CTYPE
    name/LC_MONETARY
    name/LC_NUMERIC
    name/LC_TIME
    name/LC_MESSAGES

The name of the encoding file is the <code_set_name> of the character set description file specified by the -f option, or the base name of that file when it gives none. The name of the directory name corresponds to the name argument passed to localedef. Under the directory, localedef creates the files LC_CTYPE, LC_MONETARY, LC_NUMERIC, LC_TIME and LC_MESSAGES, a category the definition leaves out taking the default values, and LC_COLLATE when the definition has that category. When the LC_CTYPE category of the definition is only a copy of another locale's, its image goes to the file source.ctype.charmap beside the directory, source the copied locale and charmap the base name of the character set description file, and name/LC_CTYPE is a symbolic link to it.

An error in the input withholds every file. So do warnings, unless -c is given; localedef then writes Warnings occurred - No output produced to stderr.

Any warning or error diagnostic messages produced by localedef are sent to stderr.

Exit Status

The localedef utility exits with the status codes listed in Table 27:

Table 27: localedef exit status 

Exit Status Meaning

0

No errors occurred. The locale database was created, or, when warnings occurred without -c, no files were written.

4

An error occurred: an invalid command line, an error in the input, or a file that could not be read or written.

Examples

Please note that the examples in this section use extensions of this implementation to the localedef utility.

The following command tries to create a locale database called german for the German locale de_DE using the ISO 8859-1 character set, and the locale definition file de_DE:

    $ localedef -f nls/charmaps/ISO-8859-1 \
    -i nls/src/de_DE german

Warnings normally prevent the successful creation of the output binary file. Since not all of the provided files are entirely clean of warnings, the following command forces localedef to produce output even in the presence of warnings. This command creates a locale database called french@euro for the French locale using the ISO 8859-15 character set, and the locale definition file fr_FR.euro:

    $ localedef -c -f nls/charmaps/ISO-8859-15 \
    -i nls/src/fr_FR.euro french@euro

This command may still produce a number of warnings, but assuming there are no errors, localedef will create a valid binary locale database. The command below makes use of the -w option to indiscriminately silence all warning messages. It creates a locale database called ja.euc in the /tmp directory from the Japanese locale definition file ja_JP using the EUC-JP encoding:

    $ localedef -c -w -f nls/charmaps/EUC-JP \
   -i nls/src/ja_JP /tmp/ja.euc
